## Auth, CSRF and sockets
- Boot (`src/index.js`): `initCsrfProtection()` starts in parallel (not awaited; its synchronous part installs the fetch/axios patches before the first render, the token fetch runs in the background, and unsafe requests await the same in-flight `ensureCsrfToken()` promise, retried on the next unsafe request if it failed). Then `preloadRoute(location.pathname)` (`routes/routeModules.js`, max `ROUTE_PRELOAD_TIMEOUT_MS` 1.5 s, never rejects) loads the current route's lazy chunk, and only then `createRoot().render(<App/>)`, so the first commit is the final page (no Suspense fallback replacing the prerendered markup). Lazy pages are `lazyWithPreload` components (`routes/lazyWithPreload.js`: a preloaded module resolves synchronously in `React.lazy`) shared by `AppRoutes.jsx` and the preload map — add new lazy routes there. Not `hydrateRoot` (UserContext reads localStorage, so markup would differ). `AuthLayout` renders the form while the profile check runs (redirects only once `loading` is false). Prerendered routes: `routes/prerenderedRoutes.js` (`/`, `/login`, `/register`, `/forgot-password`, `/privacy-policy`, `/terms-and-conditions`), rendered by `scripts/prerender.js` with `PublicAppRoutes`; it also writes `build/app-shell.html` (template with an empty `#root`, noindex, title "LangVoyage", no canonical/og:url), which the backend `front` view serves for every non-prerendered path (app pages, reset links) instead of the landing page. Tests: `routes/routeModules.test.jsx`.
- Auth = httpOnly JWT cookies set by the backend. `src/index.js` calls `initCsrfProtection()` (`utils/csrf.ts`), which globally patches `window.fetch` and the default `axios` instance: backend-origin requests get `credentials: include` and, for unsafe methods, `X-CSRFToken` (token from `/api/csrf/`, cached in sessionStorage). Pages must call the backend through `lib/api.ts` (below), which uses the `utils/axios.ts` instance; the patches remain for anything else — don't bypass `window.fetch`.
- `utils/axios.ts` — configured instance (same CSRF behaviour). `utils/auth.ts` — refresh + `clearClientSessionData()` (called on logout, 401, after login). Legacy localhost-only token fallback (`getLegacyAccessToken`) still exists for HTTP Bearer only; websockets no longer send `?token=` (the backend rejects it).
- `context/UserContext.tsx` (current user), `context/PresenceContext.jsx`.
- WebSockets: build URLs with `getWebSocketBaseUrl()` from `constants/constants.ts` (forces `wss:` on https). Chat socket lives in `pages/Conversations/features/ChatRoom.jsx`; presence socket in `layout/Layout.jsx`. Both use `utils/reconnect.ts` (exponential backoff + jitter, capped 30 s, paused while the tab is hidden), stop on close codes 1008/4401/4403 after one `refreshSessionOnce()`, reconnect once on the `session-refreshed` window event, and ignore stale sockets (per-effect `isDisposed`). Messages/deletes arrive as server `message_created`/`message_deleted` events; the client never relays them.
- Conversation list refetch policy (`pages/Conversations/api/conversationListRefetch.js`, pending PR `perf/list-refetch`): `GET /api/conversations/` is unpaginated and marks messages delivered (→ `message_status` broadcasts), so presence `conversation_update` events are patched locally where possible and otherwise refetched through a 2 s trailing debounce (`createTrailingDebounce`, flushed on `ConversationList` unmount). `resolveConversationUpdate`: `messages_read` by me → `markConversationReadInList`; by the partner → `markOwnMessagesReadInList` (my last message → read); `message_created`/`message_updated`/`message_deleted`/`message_pinned`/`message_unpinned` for the open conversation → skipped (ChatRoom applies its chat-socket event); anything else, or a conversation not in the cache (brand-new chat) → refetch. `Layout.jsx` no longer refetches on every focus: it refetches when the presence socket reconnects, on focus/visible if the tab was hidden > 60 s, or if a `conversation_update` arrived off `/conversations*` (then also on entering `/conversations*`). Tests: `api/conversationListRefetch.test.js`.
- Session refresh: the patched `window.fetch` and both axios instances refresh once (single-flight `refreshSessionOnce` in `utils/auth.ts`) and retry on a 401 (auth endpoints excluded); a failed refresh → `handleSessionExpired()` (clear session data, `/login` on protected paths). Refresh tokens rotate server-side: the refresh view re-sets `lv_refresh`, and a second tab refreshing with the old cookie within 10 s gets the same pair. Logout (`Layout.handleLogout`) POSTs `/api/logout/` so the cookie's refresh token is blacklisted (localhost legacy fallback sends `{refresh}`); options `accountDeleted` / `sessionRevoked` skip `presence/offline`.
- `BASE_URL` comes from `REACT_APP_BASE_URL` (empty in prod = same origin).

## API client, errors and observability (`src/lib/`, `src/components/`)
- **All backend calls go through `lib/api.ts`** (`api.get/post/patch/put/delete/upload`, paths `/api/...`). Core in `lib/apiClient.ts`: per-attempt timeouts (`API_TIMEOUTS` 15 s / upload 60 s / coach 35 s), GET/HEAD-only retries (max 3; network, timeout, 429, 502–504; Retry-After ≤ 10 s; jittered backoff), `AbortSignal`. It runs on `utils/axios.ts`, so CSRF + single-flight 401 refresh still apply. Errors are `ApiError` (`lib/apiError.ts`: `status, code, message, requestId, retryable, details, data`); use `getErrorMessage(err, fallback)` for UI text and `error.data` for extra 400 keys (translate). The `window.fetch` patch stays for anything else (none in src except the third-party geocoder in `pages/Profile/utils/getUserLocation.js`).
- `components/Toast` (`toast.error/success/info`, `toastApiError(err, "Couldn't …")`, `<ToastViewport/>` in `App.jsx`): failed user actions must toast, not `console.error`.
- `lib/connectivity.ts` + `components/ConnectivityBanner.tsx` (offline / "Reconnecting…"; fed by the API client and the Layout presence socket via `setSocketReconnecting`).
- `components/ErrorBoundary.tsx`: `LazyRoute` (boundary + Suspense) for every lazy route in `AppRoutes.jsx`, `RouteErrorBoundary` around the Layout `<Outlet/>`.
- `lib/logger.ts` instead of `console.*` (silent in production; `logger.error` reports to Sentry). `lib/sentry.ts` loads `lib/sentrySdk.ts` (`@sentry/react` 11.7.0, tree-shaken, ~62 KB gzip lazy chunk) after first paint, **only** when `REACT_APP_SENTRY_DSN` is set. Env: `REACT_APP_SENTRY_DSN`, `REACT_APP_SENTRY_TRACES_SAMPLE_RATE` (default 0), optional `REACT_APP_SENTRY_ENVIRONMENT`, `REACT_APP_SENTRY_RELEASE`. SDK v11 has no `sendDefaultPii`; `dataCollection` disables user info, cookies, headers, bodies, query params.
