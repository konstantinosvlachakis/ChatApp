## API and auth
- `src/config/api.ts` — base URL. Dev falls back to loopback / Android emulator / Metro LAN host. **Release (`!__DEV__`) requires `EXPO_PUBLIC_API_BASE_URL` with `https://` or the app refuses to start.**
- `src/services/api/client.ts` — axios with Bearer header and single-flight refresh-on-401, 15 s timeout (coach 35 s, uploads 60 s), GET/HEAD-only retries with backoff (network, timeout, 429, 502–504; Retry-After ≤ 30 s; max 3 attempts). Rejects with `ApiError` (`services/api/errors.ts`; `getErrorMessage`, `error.data` / `error.response.data` for raw bodies). Tokens stored via `expo-secure-store` (`src/services/storage.ts`). Refresh tokens rotate: `refreshAccessToken` stores the new `refresh` from every refresh; a failed refresh clears the tokens (logout) unless SecureStore already holds a different refresh token (an email change stored a fresh pair meanwhile).
- `src/services/connectivity.ts` (API failure streaks + presence socket state) and `src/services/toast.ts` (`showToast`, `toastApiError`), rendered by `src/components/ToastHost.tsx` (mounted once in `App.tsx`: offline/"Reconnecting…" banner + max 3 toasts). Failed user actions toast; no `@react-native-community/netinfo`.
- `src/services/monitoring.ts` — Sentry (`@sentry/react-native` ~7.2.0) only when `EXPO_PUBLIC_SENTRY_DSN` is set (`EXPO_PUBLIC_SENTRY_TRACES_SAMPLE_RATE`, default 0); no PII, scrubbed headers/bodies/emails; `wrapRoot(App)` only when enabled. Native module: needs a dev-client/EAS build (no Expo config plugin added; add it plus org/project/auth token in EAS only for source-map upload).
- `src/services/api/{auth,conversations,coach,practice}.ts`. `clearConversationsCache()` (with generation guard) runs on logout and account deletion. `auth.logout()` POSTs `/logout/ {refresh}` (5 s, errors ignored) before clearing SecureStore; `logoutAll()` → `POST /auth/logout-all/`; `deleteAccount(password)` sends `{current_password}`; `updateProfile` accepts `current_password` and stores the `tokens` pair returned after an email change.
- Sessions (`security/sessions`): ProfileScreen edit sheet shows a secure "Current password" field when the email differs from the saved one (server errors `invalid_password`/`password_required`/`throttled` shown under it). SettingsScreen: "Log out of all devices" (Alert → `logoutAll()` → `AuthContext.logout({sessionRevoked:true})`, which skips the push unregister: the server already deactivated the tokens); Delete account = Alert → `components/PasswordPromptModal.tsx` (cross-platform secure TextInput modal; `Alert.prompt` is iOS-only) → `deleteAccount(password)` → `logout()`.
- `src/context/AuthContext.tsx` — session bootstrap (any startup failure logs out — UX choice).
- WebSockets send the JWT in a header (not the URL); backend closes with 4401/4403 (auth) or 4429 (too many sockets / frame flood: RootNavigator backs off to reconnect attempt 5). **One presence socket**, owned by `RootNavigator` (`AppTabs`, keyed on user id, not re-opened on tab switches): heartbeat every 20 s (`src/services/realtime.ts`), exponential backoff + jitter reconnect (paused while backgrounded), on 4401/4403 refreshes the token once (`refreshAccessToken`, exported from `client.ts`). It fans every parsed frame out through `src/services/presenceEvents.ts` (`publishPresenceEvent` / `subscribeToPresenceEvents(handler) => unsubscribe`, like web `Layout.jsx`); the module tracks the online set and replays it as `initial_online_users` to late subscribers (reset on logout). Screens must subscribe there, never open their own `/ws/presence/`.
- Realtime refetches are coalesced: `RootNavigator` refreshes the unread badge 1 s after the first `conversation_update`/`conversations_refresh` (`scheduleUnreadRefresh`); `ConversationsScreen` refetches the list 2 s after the first event (`scheduleConversationsRefresh`; also used after send and incoming chat `message_created`), skipped if a fetch started meanwhile. `messages_read` is patched locally (own read → `unread_count` 0; other's read → own `last_message.status`) with no refetch or reorder.
