## API and auth
- `src/config/api.ts` — base URL. Dev falls back to loopback / Android emulator / Metro LAN host. **Release (`!__DEV__`) requires `EXPO_PUBLIC_API_BASE_URL` with `https://` or the app refuses to start.**
- `src/services/api/client.ts` — axios with Bearer header and single-flight refresh-on-401, 15 s timeout (coach 35 s, uploads 60 s), GET/HEAD-only retries with backoff (network, timeout, 429, 502–504; Retry-After ≤ 30 s; max 3 attempts). Rejects with `ApiError` (`services/api/errors.ts`; `getErrorMessage`, `error.data` / `error.response.data` for raw bodies). Tokens stored via `expo-secure-store` (`src/services/storage.ts`).
- `src/services/connectivity.ts` (API failure streaks + presence socket state) and `src/services/toast.ts` (`showToast`, `toastApiError`), rendered by `src/components/ToastHost.tsx` (mounted once in `App.tsx`: offline/"Reconnecting…" banner + max 3 toasts). Failed user actions toast; no `@react-native-community/netinfo`.
- `src/services/monitoring.ts` — Sentry (`@sentry/react-native` ~7.2.0) only when `EXPO_PUBLIC_SENTRY_DSN` is set (`EXPO_PUBLIC_SENTRY_TRACES_SAMPLE_RATE`, default 0); no PII, scrubbed headers/bodies/emails; `wrapRoot(App)` only when enabled. Native module: needs a dev-client/EAS build (no Expo config plugin added; add it plus org/project/auth token in EAS only for source-map upload).
- `src/services/api/{auth,conversations,coach,practice}.ts`. `clearConversationsCache()` (with generation guard) runs on logout and account deletion.
- `src/context/AuthContext.tsx` — session bootstrap (any startup failure logs out — UX choice).
- WebSockets send the JWT in a header (not the URL); backend closes with 4401/4403. **One presence socket**, owned by `RootNavigator` (`AppTabs`, keyed on user id, not re-opened on tab switches): heartbeat every 20 s (`src/services/realtime.ts`), exponential backoff + jitter reconnect (paused while backgrounded), on 4401/4403 refreshes the token once (`refreshAccessToken`, exported from `client.ts`). It fans every parsed frame out through `src/services/presenceEvents.ts` (`publishPresenceEvent` / `subscribeToPresenceEvents(handler) => unsubscribe`, like web `Layout.jsx`); the module tracks the online set and replays it as `initial_online_users` to late subscribers (reset on logout). Screens must subscribe there, never open their own `/ws/presence/`.
- Realtime refetches are coalesced: `RootNavigator` refreshes the unread badge 1 s after the first `conversation_update`/`conversations_refresh` (`scheduleUnreadRefresh`); `ConversationsScreen` refetches the list 2 s after the first event (`scheduleConversationsRefresh`; also used after send and incoming chat `message_created`), skipped if a fetch started meanwhile. `messages_read` is patched locally (own read → `unread_count` 0; other's read → own `last_message.status`) with no refetch or reorder.
- Chat UI split (`perf/mobile-chat`): `components/chat/Composer.tsx` holds the draft locally (typing re-renders only it; `ComposerHandle.activate()/isFocused()` via ref for swipe/double-tap reply; `onSend(text, attachment | null) => Promise<boolean>` clears a text draft on true (photo drafts: see Chat attachments); typing start/stop callbacks). `components/chat/MessageRow.tsx` is a `React.memo` row (Swipeable reply, reactions, long-press menu, search highlight) fed primitive flags from `renderMessage` (`useCallback`) and `dayLabelById` (`useMemo`); row handlers are stable (`useStableCallback` in the screen). Helpers in `components/chat/format.ts`. Keep row props primitive/stable or memoization breaks. Styles stay in the screen (`ConversationStyles`).
- Chat async rules (`perf/mobile-chat`): every async result that targets the open chat checks `selectedConversationIdRef`. Opening shows the chat as soon as the detail arrives (mark-read + list reload run in the background; no unread anchor on open). Pull-to-refresh uses its own `refreshingConversation` flag (list stays mounted) and merges the detail by id: it wins inside its time window, older pages and newer live messages are kept.
- Coach (`CoachChatScreen`): `sendInFlightRef` is set before the first await (no double send); `generationRef` is bumped by New conversation / mode / language change and stale replies are dropped; appends use `messagesRef` (latest list). `CommunityScreen` starts with `loading` true so the empty state does not flash.
- Chat (`ConversationsScreen`): messages/deletes/edits arrive as server `message_created`/`message_deleted`/`message_edited` events (deduped by id against the POST response; no client relay). The detail's embedded ≤200 messages are the first page; scrolling to the top loads older pages from `/conversations/<id>/messages/?page=&page_size=50`.
- Media (branch `perf/media`): `src/utils/media.ts` — `cloudinaryImage(url, { width, height?, crop })` / `avatarImage(url, size)` add `f_auto,q_auto,c_fill,g_face,w_,h_` (or `c_limit,w_`) after `/image/upload/` of `res.cloudinary.com` URLs at style size × `PixelRatio.get()` (capped at 3); other URLs (API `/media/`, file:/data:, video/raw, already-transformed) are unchanged (string parsing; RN's URL polyfill can't set `pathname`). **Always pass user images through the helper** with the dp size from the style: chat header 34 / list 44 (`ConversationsScreen`), `PartnerCard` 78, message banner 34 (`RootNavigator`), profile avatars 108, recent viewers 52, accent preview 74, own photo slots 120, public Photo Moments 140×152, Settings lists 42. Full-screen photo previews keep the original URL. Chat photo thumbnails use `cloudinaryImage(url, { width: 220, crop: "limit" })`; the viewer uses the original URL. `audioPlaybackUrl(url)` rewrites Cloudinary `/video/upload/…{.webm,.ogg}` to `.mp3` on iOS only (AVPlayer can't play WebM/Ogg web voice notes; other hosts unchanged). The app has no bundled default avatar (it uses the server's `MainAfter.jpg`).
- Chat attachments (`feat/mobile-media`):
  - `components/chat/attachments.ts` (pure): `getAttachmentKind(url, contentType?)` → `image|audio|video|file` (content type first, else extension: jpg/jpeg/png/gif/webp/heic/heif → image; mp3/wav/ogg/webm/m4a/aac → audio, so web `audio/webm` voice notes are audio; mp4/mov → video; `/media/attachments/blob_` and `/media/audio/` → audio like web `isLikelyAudio`; Cloudinary `/image/upload/` → image). `messagePreviewText` ("Photo" / "Voice message" / "Video" / "File" for attachment-only messages) feeds the list preview, pinned bar/modal, long-press menu, `RootNavigator` banner and `toReplyPreviewText`. `reply_to` has no attachment, so the screen resolves reply quotes from the loaded original (`replyPreviewById` → `MessageRow` `replyPreview`). Also `resolveImageMimeType`, `isAttachmentTooLarge` (`MAX_ATTACHMENT_BYTES` 25 MB mirrors the backend), `isOpenableUrl` (http(s) only for `Linking`).
  - `components/chat/MessageAttachment.tsx`: image in a fixed 220×240 box (`resizeMode: contain`, spinner placeholder, no layout jump) → tap opens `ImageViewer.tsx` (RN `Modal`, close button / Android back / swipe down); voice-note row (play/pause, progress, elapsed/total; after a 15 s load timeout it offers "open in browser"); file/video chip opens with `Linking.openURL`. Long-press on the attachment opens the message menu. Caption text renders below.
  - Audio: `components/chat/audioController.ts` — one `ChatAudioController` per `ConversationsScreen` (`ChatAudioContext`), one lazily created `expo-audio` player shared by all rows (only one plays). Rows read `useChatAudioState(messageId)` (`useSyncExternalStore`; non-active rows get a constant idle snapshot, so progress ticks re-render only the playing row). `release()` (pause + `player.remove()`) runs on chat switch, screen blur, app background (`AppState`), screen unmount and when the playing row unmounts. Sets `playsInSilentMode` on first play.
  - Send: `Composer` attach button → `ImagePicker.launchImageLibraryAsync({ mediaTypes: ["images"], allowsEditing: false, quality: 0.8 })` (no camera; no `expo-image-manipulator`) → type/size check (toast) → preview chip (thumbnail + remove). `onSend(text, attachment)`; with a photo the composer clears at once and restores text + photo on failure (unless a new draft was started). The screen inserts an optimistic bubble (negative id, `local_status: "sending"`, `local_mime_type`; not swipeable/pressable, clock tick, dimmed spinner) and replaces it with the POST response (dedupe by id kept); in-flight guards in both Composer and screen (`sendInFlightRef`).
  - Follow-ups: voice-note recording from mobile (`expo-audio` recorder, `audio/mp4` m4a is allowed by the backend); sending video/other files; image dimensions in the payload would allow exact aspect boxes; inline video playback.
- Push notifications (`feat/mobile-push`, `src/services/push.ts`; deps `expo-notifications`, `expo-device`): `initNotifications()` in `App.tsx` sets the foreground handler (no banner/sound for the conversation on screen — `ConversationsScreen` reports it via `setOpenConversationId` while focused), the Android channel `messages` (importance HIGH; also the plugin's `defaultChannel` in `app.json`) and the tap listener (+ `getLastNotificationResponseAsync` for cold starts). `AppTabs` (mounted only when logged in) calls `registerForPushNotifications()` 1.5 s after mount: physical devices only, needs an EAS `projectId` (`expoConfig.extra.eas.projectId` / `easConfig.projectId`; missing → one dev warning, skipped), shows a short explanation `Alert` once per install (`lv_push_permission_prompted`) before the OS prompt, then `POST /push/devices/ {token, platform}` (stored as `lv_push_registered_token`); re-registers on every start and on `addPushTokenListener`. Taps with `data.type === "message"` navigate to Chats → `ChatsHome` with the existing `openConversationId`/`openFromBannerAt` params; taps before login are queued and replayed when `AppTabs` subscribes. `AuthContext.logout` calls `unregisterPushDevice()` (`DELETE /push/devices/ {token}`, 5 s timeout, errors ignored) before clearing tokens. The in-app `RootNavigator` banner still shows for other tabs, so a foreground push can appear next to it.
- Coach history/preferences: `src/features/coachConversation.ts` (AsyncStorage, survives logout).

## Release checklist
- Set `EXPO_PUBLIC_API_BASE_URL=https://...` in EAS env / git-ignored `.env`.
- Optional: `EXPO_PUBLIC_SENTRY_DSN` (+ `EXPO_PUBLIC_SENTRY_TRACES_SAMPLE_RATE`) in EAS env; requires a new native build.
- Replace placeholder bundle id / package `com.anonymous.langvoyagemobile` in `app.json`.
- Push notifications: run `eas init` (writes `extra.eas.projectId` to the app config — `app.json` has no `extra` yet), set real bundle id/package first, then `eas credentials` → Android: upload the FCM V1 service-account key; iOS: let EAS create the APNs key with the Apple Developer account. Needs a dev-client/EAS build (Expo Go on Android SDK 53+ has no remote push). Optional: notification `icon`/`color` in the `expo-notifications` plugin once `mobile/assets` exists (the repo has no assets folder; `app.json` already points at missing `./assets/*` files). If Expo enhanced push security is on, set backend `EXPO_ACCESS_TOKEN`.
- Camera permission is disabled (`expo-image-picker` `cameraPermission: false`); microphone kept for speech recognition.
