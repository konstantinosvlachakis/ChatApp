Last verified: 2026-10-27 at commit `b57487f`; updated in PRs `fix/reliability`, `feat/api-resilience`, `perf/backend-db` (#29), `fix/chat-races` (#34), `feat/password-reset` (#37) and `feat/mobile-push` (#39, pending). ## Map
- `core/settings.py` — env-driven config; `DJANGO_ENV` picks local vs production; Sentry init (only with `SENTRY_DSN`) + `scrub_sentry_event`; `LOGGING` (console, `[request_id]` in every line, level `DJANGO_LOG_LEVEL`). `core/asgi.py` (Channels), `core/urls.py` (API under `/api/`, `/api/health/`, JSON 404 for unknown `/api/*`, `/media/`, SPA fallback; `handler500`), `core/views.py` (serves frontend build — GET/HEAD only, other methods 405; path-traversal guarded; `resolve_frontend_template`: a prerendered path gets its `build/<path>/index.html` (`/` → `index.html`), every other path the neutral `build/app-shell.html` (falls back to `index.html` when the build has no shell); `health`, `api_not_found`, `server_error`).
- `core/security_headers.py` — `SecurityHeadersMiddleware` (last middleware): `Permissions-Policy` (setting `PERMISSIONS_POLICY`) on every response, CSP on `text/html` responses only (`CSP_MODE`: `report-only` default / `enforce` / `off`; `CSP_EXTRA_CONNECT_SRC`, `CSP_EXTRA_IMG_SRC`). `chatapp/apps.py` logs a warning at startup when production throttles fall back to a per-process LocMemCache.
- `core/cache.py` — `ResilientRedisCache` (production cache backend when `USE_REDIS_REALTIME` + a Redis URL): catches `redis.exceptions.RedisError`/`OSError` in every op and fails open — `get` → default, `get_many` → `{}`, `has_key`/`touch`/`delete`/`clear` → False, `set`/`delete_many` → None, `set_many` → the keys, `add` → True (locks/guards count as acquired), `incr`/`decr` → `ValueError` (missing key: every counter caller opens a new window = allowed). Per-process circuit breaker: after a failure Redis is skipped for `CACHE_BREAKER_COOLDOWN_SECONDS` (5 s), then one caller probes; WARNING at most once per `CACHE_FAILURE_LOG_INTERVAL_SECONDS` (60 s) with the exception class only. Socket timeouts 0.5 s. `cache_degraded()` (breaker open) makes `consume_practice_generator_budget` fail **closed** (paid API; the pool/static library serves). `probe_cache()` (health) bypasses the breaker. `core/realtime.py` — best-effort channel layer: `broadcast(group, msg)` (sync, views/tokens), `safe_group_send/add/discard` (consumers), `CHANNEL_LAYER_TIMEOUT_SECONDS` (2 s) per call, own breaker (`CHANNEL_LAYER_BREAKER_COOLDOWN_SECONDS`, 5 s), rate-limited WARNING; never raises, so a broadcast failure can't fail the HTTP request (message send, logout-all, password reset…) or stop a consumer's disconnect (presence still decrements). Sockets whose `group_add` fails close with **1011** (clients back off and reconnect). `core/resilience.py` — `CircuitBreaker`, `RateLimitedLogger`.
- `core/exceptions.py` — the API error envelope: `api_exception_handler` (DRF `EXCEPTION_HANDLER`), `ApiErrorEnvelopeMiddleware` (adds `code`/`error` to hand-written `/api/` errors), helpers `error_response` / `json_error` / `error_payload`. `core/observability.py` — `RequestIdMiddleware` (first middleware; `X-Request-ID`), `RequestIdLogFilter`, request-id contextvar, `scrub_sentry_extras`, `tag_sentry_request_id`.
- `chatapp/models.py` — `Profile` (custom user: username, email, native_language, languages_practicing[list], practice_language_levels{dict}, bio, learning_goal, location, presence fields, avatar ring), `PracticeStats`, `Conversation` (sender/receiver pair), `Message` (text, attachment, reply_to, status, edited_at, pinned_*), `MessageTranslation`, `MessageReaction`, `BlockedUser`, `UserReport`, `ProfileView`, `PushDevice` (Expo push token per device: user FK, `token` unique, `platform` ios/android, `created_at`, `last_seen_at`, `is_active`). No Django admin (app, `admin.py` and `/admin/` removed; `/admin/` is just an SPA path).
- `chatapp/views.py` — most REST views (profile, community, conversations, messages, translate, react, pin, practice, coach). `auth_views.py` — JWT obtain/refresh (cookie-setting; per-email login lockout: 10 failures/h → 429 `throttled` for that email from any IP, key `auth:login_failures:v1:<sha256(email)>`, reset on success or password reset; `LOGIN_MAX_FAILURES_PER_EMAIL`, `LOGIN_FAILURE_WINDOW_SECONDS`; the same counter limits wrong `current_password` re-auth attempts), rotating refresh, logout (blacklists the refresh token from body `{refresh}` or the cookie; idempotent), `logout_all_view`, password reset (`password_reset_request_view`, `password_reset_confirm_view`; email built in `_send_password_reset_email`). `authentication.py` — cookie/Bearer JWT auth with CSRF enforcement for cookie auth; `get_user` rejects tokens whose `tv` claim != `Profile.token_version` (no extra query; a revoked cookie = anonymous). `tokens.py` — all token issuing/rotation/revocation: `issue_token_pair` (claims `tv`, `sid`, `remember_me`; records `OutstandingToken`), `LoginSerializer`, `RotatingTokenRefreshSerializer` / `rotate_refresh_token` (blacklists the used token; 10 s grace returns the same pair for a just-rotated token, cache `auth:refresh_grace:v1:<sha256(token)>`), `blacklist_refresh_token` (logout), `revoke_user_tokens` (bump `token_version`, bulk-blacklist outstanding refresh tokens, optional push deactivation, `session_revoked_event` to group `session_user_<id>` on commit). `views.verify_current_password` — re-auth for email change / account deletion. `throttles.py` — scoped throttles (`ScopedUserThrottle`: per user, per IP when anonymous, optional `methods`), `with_default_throttles(...)` (keeps anon/user) and `check_throttles(request, view, classes)` for in-view limits.
- `chatapp/consumers.py` — `ChatConsumer` (`ws/socket-server/<conversation_id>/`), `PresenceConsumer` (`ws/presence/`). `routing.py`. DB calls use `db_async` (`database_sync_to_async` with `thread_sensitive=False`: default thread pool, `close_old_connections` around each call) — never the default thread-sensitive mode, which serializes every socket in the process on one thread.
- `chatapp/push.py` — new-message push via Expo (`https://exp.host/--/api/v2/push/send`, `urllib`, 5 s timeout, ≤100 messages per POST). `MessageListView.post` calls `schedule_message_push` (no queries; `transaction.on_commit` → 2-worker thread pool, never on the request thread). The worker skips the sender and blocked pairs (either direction), sends to the recipient's active devices with its DB connection released, and sets `is_active=False` for tokens whose ticket says `DeviceNotRegistered`. Payload: title = sender username, body = text ≤120 chars or `📷 Photo` / `🎤 Voice message` / `📎 File`, `data {type:"message", conversation_id}`, `sound:"default"`, `channelId:"messages"`, iOS `threadId` `conversation-<id>`, `priority:"high"`; nothing else (no emails). There is no server "viewing this chat" signal: the app hides the banner for the chat on screen. Only message POST pushes (not edits/reactions). Tests: `tests/test_push.py` (patch `push._submit` to run inline and `push.send_expo_push_batch`).
- `chatapp/gemini.py` — coach client (key in `x-goog-api-key` header, timeouts → "coach unavailable").
- `chatapp/serializers.py` — public `ProfileSerializer` must NOT include email/date_of_birth.
- Management commands: `load_dummy_data`, `prewarm_daily_practice`. Latest migration: `0034_profile_token_version` (adds `Profile.token_version`); `rest_framework_simplejwt.token_blacklist` is in INSTALLED_APPS, so its migrations (OutstandingToken/BlacklistedToken) also run in the Heroku release phase. Django 5.2.18 (`requirements.txt`; DRF 3.16.1, SimpleJWT 5.5.1, channels 4.3.1, django-cors-headers 4.7.0 all support 5.2).

## Query performance (keep these true; tests in `tests/test_query_counts.py`)
- Any queryset serialized with `MessageSerializer` goes through `serializers.with_message_relations(qs, request.user)` (select_related sender/pinned_by/reply_to__sender + prefetch reactions and the caller's translations). Single messages re-serialized after a write use `reload_message_for_serializer`. The serializer falls back to per-row queries when not prefetched.
- `GET /conversations/<id>/` embeds only the latest `CONVERSATION_DETAIL_MESSAGE_LIMIT` (200) messages, oldest→newest; older history is `GET /conversations/<id>/messages/?page=N`. Web re-fetches page 1 right away; mobile uses the embedded list as its first page and pages older history from `/messages/` (page size 50).
- Message create/delete are broadcast to the chat room by the views (`message_created`/`message_deleted`); the chat consumer ignores client `chat`/`deleteMessage` frames. Message broadcasts strip `PER_USER_MESSAGE_FIELDS` (`serializers.message_broadcast_payload`).
- `practice_submit_view` scores a challenge once per serving: `cache.add` on `practice:scored:v1:user:{uid}:id:{hash}` (36 h); repeats return the same 200 shape with `already_scored: true` and 0 awarded; `practice_challenge_view` deletes the key when it serves that id again. Tests: `tests/test_practice.py`.
- `record_profile_view` bumps the profile cache version only when the top viewer changes (otherwise the public-profile cache never hits).
- Conversation create is a locked get-or-create on the unordered pair (no DB unique constraint; legacy duplicates resolve to the oldest).
- Conversation list: unread count is a correlated subquery; delivery marking (`mark_messages_delivered`) bumps both participants' list cache versions.
- `Message.save()` touches `Conversation.updated_at` only on create (pin/edit/status must not reorder the list).
- Slow outside calls run with the DB connection released (`views.release_db_connection()`; with the pool, close = return to pool; skipped inside `transaction.atomic`). Call it after the reads the call needs: coach (Gemini), translate (Google), practice generator (inside `fetch_generated_challenge`), message attachment upload (saved to storage *before* `Message.objects.create`, which gets the stored name; the upload is deleted if the insert fails), profile image upload. `ATOMIC_REQUESTS` is off.
- Practice: the request path (`build_challenge`) makes at most one generator call: `top_up_daily_library` adds one item to a pool below `PRACTICE_DAILY_LIBRARY_MIN_READY` under a `cache.add` lock per language/bucket/day (others serve the pool or the static library), and the realtime branch runs only if no call was made. Bulk refill is `get_or_build_daily_library` (the `prewarm_daily_practice` command).
- Community list (`profile_data:version`) is bumped only by blocks/unblocks and account deletion; registration and profile/image edits rely on the 30 s TTL.

URL names: token_obtain_pair, token_refresh, logout, logout_all, register, password_reset, password_reset_confirm, profile, delete_account, moderation_summary, presence_offline, push_devices, coach_chat, profile_data, public_profile, block_user, report_user, profile_edit, profile_location_update, update_profile_image, conversation_list, conversation_messages, mark_conversation_read, delete_message, edit_message, translate_message, react_to_message, pin_message, practice_state, practice_challenge, practice_submit.

## Security invariants (keep these true; tests in `tests/test_security.py`)
- Every conversation/message endpoint checks the user is a participant (403 otherwise). Blocking is respected.
- Chat websocket: requires auth (Bearer header, or cookie with Origin check; `?token=` is no longer accepted), numeric room id, participant only; rejections `accept()` then close (chat 4403 for any rejection, presence 4401 when unauthenticated or the account was deleted, 4429 over the per-user socket cap) so browsers see the code instead of 1006. Rejected sockets never join a group. 64 KB frame cap. Per connection: token bucket 10 frames/s (burst 20), typing 2/s (burst 4), `call_invite` 5/min; excess frames dropped silently; >100 drops/min closes with 4429. Per user: 10 chat + 5 presence sockets (cache counters `ws:connections:v1:{chat|presence}:user:{uid}`, 1 h TTL so leaks heal; per process without Redis).
- Uploads: image/video/audio only (no SVG), 25 MB attachments / 10 MB profile images, server-generated filenames, and the first bytes must match the declared type (`UPLOAD_SIGNATURE_CHECKS` in views.py; 400 "The file content doesn't match its type."). Pillow isn't installed (nothing decodes images server-side). Replacing a profile image slot deletes the old file after the save (`delete_replaced_profile_image`: only our Cloudinary cloud or `profile_images/` in default storage, never the default avatar or a file another profile references). `profile/edit/` rejects any client-supplied `profile_image_url` (400 `invalid_profile_image`).
- Cookie-authenticated unsafe requests require `X-CSRFToken` (`AUTH_COOKIE_ENFORCE_CSRF`, keep true).
- Throttles (429 envelope `throttled` + `Retry-After`; `DRF_NUM_PROXIES=1` in prod):

| Scope (env `DRF_THROTTLE_<SCOPE>`) | Default | Key | Applied to |
|---|---|---|---|
| `anon` / `user` | 300/h / 3000/h | IP / user | every view (kept via `with_default_throttles`) |
| `auth` | 20/min | IP (even when authenticated) | token, token/refresh, register, password-reset/confirm |
| `register` | 5/h | IP | register (on top of `auth`) |
| `password_reset` / `password_reset_email` | 5/h / 5/h | IP / sha256(email) | auth/password-reset/ |
| `conversation_create` + `conversation_create_daily` | 20/h + 100/day | user | conversations/ POST, only when a new conversation is created (`check_throttles` inside the view) |
| `message_send` + `message_send_daily` | 30/min + 1500/day | user | conversations/<id>/messages/ POST only (text and attachments) |
| `uploads` + `uploads_daily` | 30/h + 200/day | user | message attachments (in-view) + profile/<id>/update-image/ (shared bucket) |
| `block` | 30/h | user | block POST + DELETE |
| `translate` + `translate_daily` | 20/min + 500/day | user | messages/translate/ |
| `practice_submit` | 60/min | user | practice/submit/ (plus a 500 XP/day cap, `PRACTICE_DAILY_XP_LIMIT`) |
| `profile_view` | 120/min | user | profile/public/<username>/ |
| `people` | 60/min | user | profile/data |
| `reactions` | 120/min | user | messages/<id>/react/ |
| `report` | 20/h | user | report/ |
| `push_devices` | 30/h | user | push/devices/ |
| `logout_all` | 10/h | user | auth/logout-all/ |

  Coach (own cache counters, `cache.add`+`incr`, atomic): 12/min and 200/day per user, plus a global `COACH_GLOBAL_DAILY_LIMIT` (5000/day, 429 `coach_global_limit`).
- Registration uses Django password validators; username `^[\w.@+-]{1,30}$`; email lowercased. An existing email gets a generic 400 `registration_failed` (after hashing the password, so timing matches a real signup); `username_taken` stays specific (usernames are public).
- Password reset (`/api/auth/password-reset/`, `.../confirm/`): no auth/CSRF (like login/register); the request endpoint always returns the same 200 (no enumeration), sends the email on a background thread so response time doesn't reveal whether the account exists (`PASSWORD_RESET_EMAIL_ASYNC`, default true; tests set it false), and never logs the address; links use `default_token_generator` (`PASSWORD_RESET_TIMEOUT` 1 h, single use because the token hashes the password); confirm checks the token before running `validate_password`; success clears the login lockout and the auth cookies and revokes every session (`revoke_user_tokens(..., deactivate_push=True)`). Tests: `tests/test_password_reset.py`, `tests/test_sessions.py`.
- Sessions (`security/sessions`; tests `tests/test_sessions.py`): `SIMPLE_JWT` `ROTATE_REFRESH_TOKENS`/`BLACKLIST_AFTER_ROTATION` = True (implemented in `tokens.py`, which every token path must use). Refresh reuse after the grace → 401 `token_not_valid`. Logout blacklists one refresh token (its access token lives ≤1 h). `POST /api/auth/logout-all/` (auth, `logout_all` throttle) revokes everything incl. the caller and deactivates push devices. Email change in `profile/edit/` and `DELETE profile/delete/` need `current_password` (400 `password_required` / 403 `invalid_password` / 429 `throttled` via the login lockout); an email change revokes other sessions but keeps the caller's `sid` (fresh pair: body `tokens` for Bearer, cookies for cookie auth). Websockets: `tv` checked on connect inside the first query (4401), and `session_revoked_event` closes older-version sockets with 4401.
- Coach: mode allow-listed, language sanitised, 2000-char cap, 200/day per user. Messages/translation capped at 5000 chars.
- Errors return generic messages; details are logged, never returned. Every API error uses the envelope `{error, code, ...}` (5xx include `request_id`); keep `error` a string. Legacy `message` (token) / `detail` (coach, DRF errors) keys stay one release.
- `/api/health/` stays AllowAny, unauthenticated and unthrottled, and never returns hosts or exception text. Checks `database` (critical), `cache` and `channel_layer` (real round trips that bypass the breakers; each reports `breaker: open|closed`): 200 `{status: "ok"|"degraded", checks}` (degraded = Redis down, the app fails open), 503 `status: "error"` only when the database fails. Tests: `tests/test_redis_resilience.py` (failing Redis client + failing channel layer: csrf, login, refresh, password reset, message send, logout-all, coach, throttles, health, 1011 sockets, breaker/logging), `tests/test_api_resilience.py` (`FrontendTemplateTests`).

## Open issues
Sessions: a logged-out access token stays valid ≤1 h (only the refresh token is blacklisted); `OutstandingToken`/`BlacklistedToken` rows are never pruned (schedule `manage.py flushexpiredtokens`); a refresh whose response is lost (network) logs that device out once the 10 s grace passes; the grace cache is per process without Redis; a socket that joins `session_user_<id>` in the instant after a revocation broadcast stays open until it reconnects; ws revocation needs the Redis channel layer to reach other dynos; password reset sends SMTP inside the request (timing side channel on account existence; a queue/thread would fix it); production needs `EMAIL_HOST` and friends set or reset emails only reach the dyno log; `/media/` unauthenticated; no DB uniqueness on conversation pairs (needs a duplicate-merge migration); practice replay farming (double submits/replays of a served id fixed; unserved known `dailygen:` ids still scorable once, guard per process without Redis); presence ignores blocks; non-numeric `message_id` in translate → 500; throttles, login lockout and websocket caps per-process without Redis (warned at startup in production); the login lockout lets anyone lock an account for an hour by failing 10 logins (password reset lifts it); push tokens move to the last account that registers them (no proof of possession; the old owner just stops receiving pushes); CSP is report-only until checked in browsers; `createsuperuser` just creates a regular account (no admin).
