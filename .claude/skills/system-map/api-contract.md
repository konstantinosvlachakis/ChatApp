## Email verification (2026-10-31; security/email-verification, based on 77b0f5f)

- Own `/api/profile/` and profile edit's `updated_profile` expose `email_verified: boolean`. Public profiles expose neither verification state nor code records. Registration returns `email_verified: false` and `verification_email_sent` (background delivery may still fail).
- Authenticated POST `/api/auth/verify-email/send/` replaces the code and returns `{message, email, expires_in: 900, email_verified: false}`; already verified returns `{message, email_verified: true}`. Database limits: 3 sends/600 s and 10/day, including signup/email-change sends. Additional DRF scopes limit sends per user and IP (30/h). 429 includes `retry_after` and `Retry-After`.
- Authenticated POST `/api/auth/verify-email/confirm/` takes `{code: "012345"}`; success `{message, email_verified: true}`. 400 codes: `invalid_code` (wrong six-digit guesses include `attempts_remaining`), `code_expired`, `too_many_attempts`. Five guesses per code; 30 confirmations/h.
- Public POST `/api/auth/verify-email/confirm-link/` takes `{token}` from `/verify-email?token=...`. Signed token binds user/address fingerprint/token version, expires in 24 h, and never signs in. Bad links return 400 `invalid_link`.
- Unverified accounts get 403 `email_unverified` on conversation creation, message/photo send/edit, reactions and Lumi. Reads, People, Practice, profiles and Settings remain open. Web's axios interceptor opens `EmailVerificationGate`; mobile's API client publishes the central verify prompt. Both clients treat a missing flag from an older backend as verified for reminders; backend permissions always enforce current state.

## Auth and transport conventions

- **Base path** `/api/` (`backend/core/urls.py` includes `chatapp.urls`). Web: every call goes through `frontend/src/lib/api.ts` (`api.get/post/patch/delete/upload("/api/...")`, which prefixes `BASE_URL` = `REACT_APP_BASE_URL`, empty = same origin). Mobile: axios `api` instance with `baseURL = ${API_BASE_URL}/api` (`mobile/src/services/api/client.ts`), so mobile paths have no `/api` prefix.
- **Trailing slashes matter.** Every path ends in `/` except `profile/data`. An unknown `/api/...` path (including a missing slash) returns a **JSON 404** envelope (`core/urls.py` `api_not_found`, before the SPA catch-all). Non-API unknown paths still get the SPA `index.html` for GET/HEAD, but any other method gets **405** (`core/views.py:front`).
- **Auth class** `chatapp/authentication.py:CookieOrHeaderJWTAuthentication` (the default). It tries `Authorization: Bearer <jwt>` first (mobile; the values `null`/`undefined` are ignored), then the `lv_access` cookie (web). The default permission is `IsAuthenticated`.
- **CSRF**: cookie-authenticated unsafe methods need the `X-CSRFToken` header (`AUTH_COOKIE_ENFORCE_CSRF`, default true). If it is missing, the response is 403 `{"detail":"CSRF Failed: ..."}`. Web gets the token from `GET /api/csrf/`, caches it in sessionStorage `csrfToken`, and attaches it automatically through the patched `window.fetch` and axios (`frontend/src/utils/csrf.ts`). Bearer requests (mobile) are exempt.
- **JWT** (`chatapp/tokens.py`): access token lasts 1 h, refresh token 7 d (30 d with `remember_me`, kept across rotations by the `remember_me` claim). Claims added to every pair: `tv` (= `Profile.token_version`; missing = 0), `sid` (session id, kept across rotations), `remember_me`. Refresh **rotates**: every refresh returns `{access, refresh}` and blacklists the used token (`rest_framework_simplejwt.token_blacklist`); reusing it → 401 `token_not_valid`, except within 10 s of its rotation, when it answers with the same new pair (grace for two tabs / retries). `CookieOrHeaderJWTAuthentication.get_user` rejects tokens whose `tv` != the user's `token_version` (no extra query); a revoked/expired cookie counts as anonymous. Bumping `token_version` (password reset, email change, log out of all devices, account deletion) revokes every token; logout blacklists one refresh token (the access token lives out its ≤1 h).
  - Web: `POST /api/token/` sets the httpOnly cookies `lv_access`/`lv_refresh`. `utils/auth.ts:refreshSession` POSTs `/api/token/refresh/` with an empty body (the cookie is used). Every backend request through the patched `window.fetch` or either axios instance refreshes once (single-flight `refreshSessionOnce`) and retries once on a 401, except auth endpoints; a failed refresh clears session data and redirects protected pages to `/login` (flows §1).
  - Mobile: stores `access`/`refresh` from the response body in SecureStore. `client.ts` uses a single-flight refresh-on-401 (body `{refresh}`) and stores the rotated refresh token; a failed refresh clears the tokens (logout) unless SecureStore already holds a newer pair (email change raced the refresh).
- **Throttles** (settings `REST_FRAMEWORK`, every rate overridable by env `DRF_THROTTLE_<SCOPE>`): global anon 300/h and user 3000/h. A view with explicit `throttle_classes` replaces the defaults, so scoped views use `with_default_throttles(...)` (`chatapp/throttles.py`) to keep them. Throttled → 429 envelope `throttled` + `Retry-After` + `retry_after`. Per user when authenticated, per IP otherwise:
  - `auth` 20/min per IP (even when authenticated): token, token/refresh, register, auth/password-reset/confirm. `register` 5/h per IP on top for register.
  - `password_reset` 5/h per IP **and** `password_reset_email` 5/h per address (sha256 of the lowercased email): auth/password-reset/.
  - `conversation_create` 20/h + `conversation_create_daily` 100/day: conversations/ POST, counted only when a new conversation is created.
  - `message_send` 30/min + `message_send_daily` 1500/day: conversations/<id>/messages/ POST.
  - `uploads` 30/h + `uploads_daily` 200/day, one bucket for message attachments and profile image uploads.
  - `block` 30/h (block + unblock), `translate` 20/min + `translate_daily` 500/day, `practice_submit` 60/min, `voice_next` 60/min, `voice_complete` 30/min, `profile_view` 120/min (public profile), `people` 60/min (profile/data), `reactions` 120/min, `report` 20/h, `push_devices` 30/h, `logout_all` 10/h (auth/logout-all/).
  - Login lockout (not a DRF throttle): 10 failed logins for one email within an hour → token/ answers 429 `throttled` (+ legacy `message`, `Retry-After` 3600) for that email from any IP until the window ends; reset by a successful login or a password reset.
  - Coach has its own atomic cache limits: 12 requests per 60 s and 200 per day per user, and a global 5000/day (`COACH_GLOBAL_DAILY_LIMIT`, 429 `coach_global_limit`).
- **Pagination**: two hand-rolled page-number endpoints (not DRF paginators), `profile/data` and `conversations/<id>/messages/`. Both take `?page=&page_size=` and return `pagination:{page,page_size,total_pages,total_count,has_next,has_previous}`. An out-of-range page returns an empty list, not 404. Other lists are unpaginated.
- **Error envelope (every API error)**: `{"error": "<human-readable message>", "code": "<machine_code>"}` plus optional `details` (validation field errors), `retry_after` (seconds, 429), `request_id` (5xx). `error` is always a string.
  - DRF exceptions go through `core/exceptions.py:api_exception_handler` (settings `EXCEPTION_HANDLER`): ValidationError → 400 `invalid` + `details`; NotAuthenticated 401 `not_authenticated` / AuthenticationFailed 401 (`authentication_failed`, simplejwt `token_not_valid`); PermissionDenied 403 `permission_denied` (CSRF failure: `csrf_failed`); NotFound/Http404 404 `not_found`; MethodNotAllowed 405 `method_not_allowed`; UnsupportedMediaType 415 `unsupported_media_type`; Throttled 429 `throttled` + `Retry-After` header + `retry_after`; anything unhandled → 500 `server_error`, generic message, `request_id`, traceback logged.
  - Hand-written view errors keep `{"error"}` and get a `code`: explicit ones (`not_participant`, `blocked`, `already_translated`, `same_language`, `username_taken`, `email_taken` (profile/edit only), `registration_failed` (register, existing email), `invalid_profile_image`, `invalid_json`, `translation_unavailable`, coach `message_too_long`/`coach_rate_limited`/`coach_daily_limit`/`coach_global_limit`/`coach_quota`/`coach_unavailable`) or a default per status added by `ApiErrorEnvelopeMiddleware` (400 `invalid`, 403 `permission_denied`, 404 `not_found`, 502 `upstream_error`, 503 `service_unavailable`, ...).
  - **Legacy keys kept for one release** (older mobile builds): token errors also carry `message` (= `error`), coach errors and DRF-generated errors also carry `detail` (= `error`). Remove after the next mobile release.
  - translate 400s still add the flags `already_translated` / `same_language` (and `translated_text`).
- **Request ids**: `core/observability.py:RequestIdMiddleware` (first middleware) accepts an incoming `X-Request-ID` (≤64 chars, `[A-Za-z0-9-]`) or generates a uuid4 hex, and sets `X-Request-ID` on **every** response. Log lines include it (`LOGGING` format `[%(request_id)s]`); 500 envelopes include it as `request_id`; Sentry events are tagged with it. Websocket consumers log errors with a per-connection `ws-<hex>` id.
- **Client error handling**: web `lib/api.ts` / mobile `services/api/client.ts` turn every failure into `ApiError {status, code, message, requestId, retryable, details, data}` (message from `error`, falling back to `message`/`detail`, then friendly text per status; no response → `network_error`, timeout → `timeout`, caller abort → `aborted`). Only GET/HEAD are retried (max 3 attempts; network errors, timeouts, 429, 502, 503, 504; Retry-After respected). See flows §13.
- **Media URLs**: `build_media_url` / `ProfileSerializer.get_profile_image_url` return absolute URLs and force https on herokuapp/langvoyage hosts. The **exception** is `profile/moderation/`, which returns the raw stored `profile_image_url`. Clients resolve it themselves (web `Settings/page.jsx` prefixes `/media/`; mobile uses `resolveMediaUrl`).
- **WebSockets** (not REST, listed for completeness): `ws/socket-server/<conversation_id>/` and `ws/presence/` (`chatapp/routing.py`, `consumers.py`). REST writes push events to the chat group: `message_created_event`, `message_edit_event`, `message_reaction_event`, `message_pin_event` (carrying a serialized Message **without** per-user fields), `message_deleted_event` (`message_id`), `message_status_event` (`message_ids`, `status`, `actor_id`), and `conversation_update_event` (`conversation_id`, `trigger`, `actor_id`) to the presence groups.

## Shared payload shapes

- **ProfileSummary** (`serializers.py:ProfileSerializer`, other users only): `{id, username, native_language, profile_image_url (abs URL|null), is_online (true only if last_seen < ONLINE_FRESHNESS_SECONDS=90 ago), last_seen}`. It must never gain `email` or `date_of_birth`.
- **OwnProfile** (`profile_view`): `{user_id, username, age, location, location_updated_at, native_language, base_translate_language, languages_practicing[str], practice_language_levels{lang: beginner|intermediate|advanced|fluent}, profile_image_url, complementary_image_1_url, complementary_image_2_url, avatar_ring_color (default "#1b7f79"), date_of_birth, email, bio, learning_goal, recent_profile_viewers[{user_id, username, native_language, profile_image_url, viewed_at}] (max 12), support_email}`. Cached per user for 5 min. Note that the id key is `user_id`, not `id`.
- **PublicProfile** (`public_profile_view`): `{user_id, username, age, native_language, languages_practicing, practice_language_levels, profile_image_url, complementary_image_1_url, complementary_image_2_url, bio, learning_goal, reviews: [] (always empty), is_blocked_by_me, has_blocked_me}`. It has no email, date_of_birth or location.
- **PeopleCard** (`profile_data_view` items): `{username, native_language, languages_practicing, practice_language_levels, learning_goal, profile_image_url, city, active_label, is_new, match:{teaches_me, learns_mine, reciprocal, score, they_teach, they_learn, you_speak}}`. It has no id, bio, premium flag, location, last_seen or is_online. `they_teach` = their native language when I practise it (else null); `they_learn` = the first language they practise that I speak (else null); `you_speak` = how I speak `they_learn` (`native`|`advanced`|`fluent`|null). `city` = first part of their `location` ("City, Country"), or null; never the country or coordinates. `active_label` = "Active today" (online or seen in 24 h) / "Active this week" (7 days) / null, never the exact time. `is_new` = joined in the last 7 days (`date_joined`; NULL = older account, never new). Added fields are optional for clients.
- **Message** (`serializers.py:MessageSerializer`):
  - Fields: `{id, text, sender: ProfileSummary, status: sent|delivered|read, attachment (raw storage path), attachment_url (abs|null), kind: text|sticker|gif, media|null, timestamp, edited_at|null, is_pinned, pinned_at|null, pinned_by:{id,username}|null, reply_to:{id, text, kind, media, timestamp, sender:{id, username}}|null, translated_text|null, translated_source_language|null, can_translate, reactions:[{id, user_id, username, emoji}] (oldest first), current_user_reaction: emoji|null}`.
  - `kind`/`media` (`feat/stickers-gifs-api`): `text` = today's text and/or attachment, `media` null. `sticker`: `text` "", no attachment, `media {pack, id, label, url}` (`url` = absolute static URL of `chatapp/static/stickers/<pack>/<id>.svg`, resolved at serialization; null with label "Sticker" if the sticker left the manifest). `gif`: `text` "", no attachment, `media {provider:"giphy", id, title, url, preview_url, still_url|null, width, height}` (https GIPHY media hosts only; `url` 200 px wide, webp when available). Older clients that ignore `kind` see an empty-text message. Sticker/GIF messages are never translatable or editable.
  - `current_user_reaction` remains a legacy single-emoji hint (the caller's first reaction); both clients use `reactions[]` and their user id to mark each selected emoji.
  - The translation fields are **per requesting user**, for that user's `base_translate_language`.
  - `can_translate` is false for your own messages, for empty text, and when a translation already exists.
  - Querysets must go through `with_message_relations` (query-count tests).
  - Corrections (`feat/corrections-phrasebook-api`): `correction_requested` (bool, the sender asked for corrections), `accepts_corrections` (bool, not per viewer: text message with text whose sender's `correction_preference` is `often`, or `when_asked` + `correction_requested`), `corrections: [{id, corrector:{id, username}, corrected_text, note, created_at, updated_at}]` (oldest first, one per corrector; timestamps are ISO strings). ProfileSummary adds `correction_preference: often|when_asked|off`.
- **PhrasebookEntry** (`phrasebook.entry_payload`): `{id, text, meaning, note, context, language (lowercase name or ""), source: manual|message|translation|correction, source_message_id|null (null once the message is deleted; the text is a copy), source_conversation_id|null, created_at, updated_at, due_at, interval_days, repetitions, lapses, review_count, last_reviewed_at|null}`. Private to its owner.
- **ConversationListItem** (`ConversationSerializer`, list context): `{id, sender: ProfileSummary, receiver: ProfileSummary, created_at, updated_at, last_message: Message|null, unread_count (messages from the other user with status != read), pinned_messages: [] (empty in list), messages: [] (empty in list)}`.
  - Ordered `-updated_at`. `updated_at` only changes when a message is created.
  - Cached per user for 20 s and invalidated by version bumps.
  - `sender`/`receiver` mean the conversation creator and the other participant, **not** the viewer. Clients pick "the other" by comparing ids.
- **ConversationDetail** (`include_messages=True`): same keys as the list item, plus:
  - `messages`: the latest `CONVERSATION_DETAIL_MESSAGE_LIMIT=200` messages (`serializers.py`), oldest→newest.
  - `pinned_messages`: **all** pinned messages, newest pin first.
  - `last_message` is taken from the embedded list.
- **PracticeStats**: `{points, xp, level, correct_answers, total_answers, accuracy (% 1dp), preferred_language}`. **Leaderboard entry**: `{rank, username, points, level, xp, is_current_user, profile_image_url (absolute URL like PeopleCard, or null)}` (top 10; falls back to the global board when the language has no entries). **Challenge**: `{id, sentence_parts, options[str], hint, difficulty_bucket, language, source: library|generator|generator_daily, round_complete: bool}`. `round_complete` is true only on the first challenge of a new round (the user has now seen every library sentence of that level, or every item of today's generator pool); web shows a chip on the drill card, mobile a chip above the sentence. Challenge ids look like `lang:bucket:idx`, `gen:...` or `dailygen:day:lang:bucket:idx`.
- **PracticeProgress** (`practice_progress.serialize_language_progress`, `feat/practice-levels`): `{language, bucket (1-3), max_bucket (3), bucket_label: "Basics"|"Everyday grammar"|"Advanced grammar", cefr: "A1"|"A2–B1"|"B1–B2", attempts_in_bucket, window_size, window_accuracy (0–1, 3 dp, null before the first answer), needed_for_promotion: {attempts_remaining, min_attempts, accuracy_target} | null (top bucket), can_promote (a higher bucket exists), change: null|"promoted"|"demoted" (only on the submit that moved the bucket)}`. Web `pages/Practice/LanguageLevel.jsx` (`practiceUtils.progressSummary` / `levelChangeMessage`), mobile `PracticeScreen` level card + banner (`features/practiceLevel.ts`).
- **VoiceSentence** (`practice_voice_next_view`): `{id: "voice:lang:bucket:idx", text, language, bucket (1-3), round_complete, pass_threshold (0.62|0.68|0.72), translation_hint? (English gloss, non-English items)}`. **VoiceComplete** (`practice_voice_complete_view`): `{id, language, passed, pass_threshold, awarded_xp, awarded_points, already_scored, daily_limit_reached, daily_voice_limit_reached, daily_xp_limit_reached, awards_unavailable, reason: awarded|below_threshold|not_served|already_scored|daily_voice_limit|daily_xp_limit|unavailable, stats: PracticeStats, leaderboard[], current_rank}`.

### Non-API routes (backend/core/urls.py)

- No Django admin: `/admin/` is an ordinary SPA path (GET → index.html, POST → 405).
- Security headers on every response: `Permissions-Policy` (camera/microphone/geolocation self), `Cross-Origin-Opener-Policy: same-origin`; HTML responses also get `Content-Security-Policy-Report-Only` (`CSP_MODE=enforce` to enforce; `core/security_headers.py`).
- Root static files from the frontend build: `favicon.ico`, `manifest.json`, `robots.txt`, `sitemap.xml`, `logo192/512.png`, `coach-avatar-favicon.svg`.
- `media/<path>`: served unauthenticated. This happens when DEBUG is on (both urlconfs add `static()`), or in prod with local storage. With Cloudinary, URLs point to Cloudinary directly.
- `^api(?:/.*)?$` → `core/views.py:api_not_found`: JSON 404 envelope for unknown API paths (csrf-exempt, any method).
- `^.*$` → `core/views.py:front`: prerendered `<path>/index.html` (`/` → `index.html`) for prerendered public routes, otherwise the neutral `app-shell.html` (fallback `index.html`; path-traversal guarded) for GET/HEAD; **405** (`Allow: GET, HEAD`) for other methods (csrf-exempt).
- `handler500 = core.views.server_error`: JSON envelope for `/api/` paths, Django's default page otherwise (only reached for errors outside DRF views).

## Cross-client coupling / change checklist

- **The 200-message cap.** Mobile's first page of chat history is `GET /conversations/<id>/` `messages` (`CONVERSATION_DETAIL_MESSAGE_LIMIT=200`, `serializers.py`); it mirrors that number as `DETAIL_MESSAGE_LIMIT` in `ConversationsScreen` to decide whether older pages exist and where `/messages/` paging (50 per page) starts. Change both together. Web pages older messages via `/messages/?page=N` (30 per page). Both treat `has_next` as "older exist". Keep pages newest-first, with each page's array chronological.
- **Mobile pinned list.** Mobile rebuilds `pinned_messages` locally from the loaded messages after any change (`buildPinnedMessages` in ConversationsScreen). Pins older than the latest 200 disappear on mobile after the first local update. Web uses the server's `pinned_messages` (detail and every `/messages/` page).
- **Message send is multipart only.** Both clients send FormData. Adding a JSON parser is safe; removing the multipart parser breaks both. The text field is `text`, the reply field is `reply_to` (string id), and the file field is `attachment`.
- **Message shape.** `kind`/`media` are additive: a client that doesn't know a `kind` should render it as a generic "Sticker"/"GIF" placeholder, never as an empty bubble. Web and mobile both render `sender.id/username`, `status` ticks, `reply_to.{id,text,sender.username}`, `reactions[]` and `current_user_reaction`, `is_pinned` and `pinned_by`, `edited_at`, `attachment_url` and `translated_text`/`can_translate`. Web also tolerates `attachmentUrl` (camelCase from the old ws relay, still set on optimistic messages). Renaming any of these breaks both clients and the ws payloads (`message_*_event` carry the serialized Message minus per-user fields).
- **`sender`/`receiver` on a conversation** are creator and other participant, not "me" and "them". Both clients derive the partner by id. Don't change their meaning.
- **List item vs detail.** List items return `messages: []` and `pinned_messages: []`. Mobile's `Conversation` type marks `messages` as required, so keep the key present (empty) in list responses.
- **`unread_count`** = messages from the other user with `status != "read"`. Web ChatRoom and mobile use it to find the first-unread anchor (web walks older pages until it is found).
- **GET side effects.** The list, detail and `/messages/` GETs all mark messages `delivered` and broadcast. Clients rely on this for delivery ticks; there is no separate "delivered" endpoint.
- **`profile/data`**:
  - No trailing slash. Keep the `match_only` legacy param, which tests cover; no current client sends it.
  - Web and mobile send `section` (+ the filter params) and read `pagination.{has_next,total_count}`, `total`, `filters`, `counts` and `match.{teaches_me,learns_mine,reciprocal,they_teach,they_learn,you_speak}`, `city`, `active_label`, `is_new` (mobile: `PeopleCard`/`PeopleFilterInfo`/`ProfileListResponse` in `types/index.ts`). Older mobile builds still send `match` (+ `level`): keep it working.
  - Items have no `id`, and both clients key cards by `username`.
  - Neither client has segments any more: both show Perfect exchanges (`section=perfect`) above More people to meet (`section=others`), with quick filters (near/active/new/my_level) and a filter panel (they_speak/they_learn/level/include/sort). Renaming a param or label needs both clients.
- **Own-profile id is `user_id`** (profile/ and public profile), while ProfileSummary uses `id`. Web compares `message.sender.id === user.user_id`, and mobile uses `user.user_id` for the update-image URL. Mobile `ProfileScreen` merges `updated_profile` from `profile/edit/`, and the image upload response is merged by both clients.
- **Translate 400 bodies are part of the contract.** Web disables the translate button on `already_translated`/`same_language`. Mobile shows `translated_text` from the 400 `already_translated` body, and practice translate (both clients) skips targets on `same_language`.
- **One error envelope.** Every API error has `error` (string) + `code`; clients only read them via `ApiError` (web `lib/apiError.ts`, mobile `services/api/errors.ts`). The legacy `message` (token) and `detail` (coach + DRF errors) keys stay for one release for older mobile builds; drop them together after that. New errors: return `error_response(message, code, status)` (`core/exceptions.py`) or raise a DRF exception — never a bare `{detail}`.
- **Retries are GET/HEAD only.** A new unsafe endpoint never gets retried by the clients; a new GET must be safe to repeat (the existing GET side effects — delivery marking, profile-view recording — are idempotent).
- **Register uses camelCase** (`nativeLanguage`, `practiceLanguages`, `practiceLanguageLevels`, `dateOfBirth`), and both clients send camelCase. Older clients may still send `practiceLanguage`/`practiceLevel`. profile/edit uses snake_case (`native_language`, `languages_practicing`, `practice_language_levels`, `date_of_birth`).
- **Moderation summary image URLs are raw.** Both clients resolve them with a `/media/` prefix. If you switch to `build_media_url`, make sure the clients' resolvers accept absolute URLs (they do, via `startsWith("http")`).
- **Refresh rotates.** Every client that refreshes must store the returned `refresh` (mobile SecureStore; web gets cookies). Logout sends the refresh token (mobile body, web cookie) so it is blacklisted. Anything that issues tokens must go through `chatapp/tokens.py` (`issue_token_pair`) so they carry `tv`/`sid` and are recorded as outstanding.
- **CSRF.** Any new unsafe endpoint called from web needs no client work (global patch), as long as it goes through `window.fetch` or axios against the `BASE_URL` origin. Endpoints with `authentication_classes([])` skip CSRF.
- **Blocking.** `POST block/` deletes the shared conversations. Public profile returns 403 when either side blocked. The conversation POST and message POST return 403 if blocked. People lists exclude blocked users in both directions.
- **Server-side message broadcasts.** New messages and deletes are broadcast by the views (`message_created` / `message_deleted`); clients must not relay them and must dedupe by id against their own REST response. Broadcast payloads omit `PER_USER_MESSAGE_FIELDS` (`serializers.py`); if you add a per-user Message field, add it there and make both clients tolerate its absence.
